# GPU (CUDA) requirements — NOT installed into this repo's `.venv`.
#
# WHY THIS FILE EXISTS (2026-09-06)
# ---------------------------------
# `W3_neural_long_run13` recorded `torch 2.11.0+cu128`, `cuda_available: true`,
# an RTX 5060 Laptop GPU and `sm_120`, while `.venv/Scripts/python -c
# "import torch"` reported `2.11.0+cpu`. The reviewer's two hypotheses were
# "a different interpreter ran W3" or "torch was downgraded afterwards".
#
# It was the FIRST one, and the filesystem settles it:
#
#   .venv/Lib/site-packages/torch-2.11.0.dist-info/RECORD   2026-03-31 11:22
#   .venv/Lib/site-packages/           (dir mtime)          2026-08-27 17:35
#     -> no package was added or removed from the venv after 2026-08-27, so the
#        venv's torch has been the CPU build continuously since 2026-03-31 and
#        was never downgraded.
#
#   C:\Users\mrthn\AppData\Local\Programs\Python\Python312
#     torch-2.11.0+cu128.dist-info/RECORD                   2026-09-05 11:49
#     -> the CUDA build was installed into the SYSTEM Python 3.12 ninety
#        minutes before the W3 runs (13:30-14:07 on 2026-09-05).
#
# So the GPU numbers are real and were produced by a real GPU; what was missing
# was any record of WHICH interpreter produced them. `resolve_device()` now
# stamps `python_executable`, `python_version` and `torch_file` onto every
# neural receipt so the question cannot be asked again.
#
# THE TWO INTERPRETERS ARE THE SAME BINARY (refined 2026-09-06)
# --------------------------------------------------------------
# `.venv/pyvenv.cfg` reads:
#     home       = %LOCALAPPDATA%\Programs\Python\Python312
#     executable = ...\Python312\python.exe
#     version    = 3.12.10
#     include-system-site-packages = false
#
# So the venv and the "GPU interpreter" are ONE python.exe with TWO package
# sets. The venv's own `torch 2.11.0+cpu` SHADOWS the base install's
# `torch 2.11.0+cu128`; the venv launcher is a trampoline that execs the base
# binary with the venv's site-packages in front. Confirmed by watching the fast
# suite: the venv's `python.exe -m pytest` sat at 4 MB and 0 s of CPU while its
# CHILD, the base Python312 `python.exe`, carried 618 s and 1.3 GB.
#
# CONSEQUENCE FOR THE INSTALL BELOW: run it against the BASE interpreter and
# NOT from inside an activated venv. Inside the venv, pip installs into the
# VENV's site-packages -- `torch.cuda.is_available()` there flips to True, the
# base install is untouched, and the environment W3 actually ran on has not
# changed. Both outcomes "work"; only one is the one the receipts name.
#
# THE DESIGNATED GPU INTERPRETER
# ------------------------------
#   C:\Users\mrthn\AppData\Local\Programs\Python\Python312\python.exe
# Override with the environment variable AEGIS_GPU_PYTHON.
#
# THE INSTALL LINE (run it with THAT interpreter, never with .venv's):
#
#   & "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -m pip install \
#       --index-url https://download.pytorch.org/whl/cu128 \
#       torch==2.11.0+cu128
#
# A plain `pip install -r backend/requirements.txt` into that interpreter will
# NOT undo this (torch is not listed there), but a `pip install torch` from
# PyPI WILL silently replace it with the CPU build. `test_gpu_environment_pin.py`
# fails on this laptop the moment that happens, and skips on any host without an
# NVIDIA GPU.
torch==2.11.0+cu128   # --index-url https://download.pytorch.org/whl/cu128
