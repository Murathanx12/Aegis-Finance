# Write-only telemetry — measured, never asked

Generated by `scripts/write_only_telemetry_audit.py`. Regenerate rather
than edit.

A field written and never read is not a tidiness problem. It is a
question that was **measured and never asked**. `decision_lag_minutes`
was on every IIF-1 receipt and read by nothing — and the two clocks a
launch guard needed were sitting on disk the entire time, which is why
the guard ended up calibrated on the wrong one.

Each row below needs a decision: **wire it up, or delete it.** Leaving
it is the only wrong answer, because inert telemetry looks exactly like
working telemetry.

- fields examined: **806**
- WRITE_ONLY: **167**
- excluded by threshold: **0** (named in
  the JSON — a silent exclusion is how this audit first hid its own
  motivating case, `decision_lag_minutes`)
- TEST_ONLY: **31** — a test asserting the field was
  written proves the WRITER works, not that anything consumes it.
  `decision_lag_minutes` had exactly this shape.

*Method: a field counts as READ on 2+ production mentions, which is deliberately generous: the writer itself is one mention, and a false 'read' makes this audit quieter, which is the safe direction for a work list.*
