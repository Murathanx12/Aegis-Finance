## 1. Mission and end state

Build a self-improving investment intelligence system that maximises portfolio utility under a declared personality (preservation / balanced / aggressive / extreme growth). There are three deliverables:

1. **Murat's own capital.** Paper first; real money only through the attended CAPITAL_CANDIDATE gate.
2. **A public, accessible TOOL; the source code and research stay protected** (amended 2026-11-09). People use Aegis as a hosted product (site, API, desktop app), never as a repository to copy. The licence is All Rights Reserved. A public repository can be read and scraped by AI crawlers whatever its licence says, so in the end state **the source repo is private**, and the public surface is the hosted tool plus a curated showcase. See OD-9.
3. **An HKU paper**, if a novel and defensible result emerges.

## 2. The architecture this roadmap is organised around

```
              ┌──────────────── M5 LEARN (grades, priors, source weights) ───────────────┐
              ▼                                                                           │
  M1 SENSE ──► M2 UNIVERSE (the hub) ──► M3 DECIDE ──► M4 ACT ──► outcomes ──────────────┘
  news, reader,   dated candidate set,     books, branching,   paper accounts,
  official, macro, every name tagged with   overlays, owner      contest, PC-PAPER
  analysts, Asia   WHY it is in + age        hypotheses
                                │
                                └──► M6 SHOW: the public tool (results, universe map, alerts)
  M0 FOUNDATION underneath everything: runtime = a commit, storage, CI, budget, agent workflow
```

**The universe is the hub.** Every module connects to it through one contract:

| Module | Its contract with the universe |
|---|---|
| M1 SENSE | Every output maps to issuer ids, so it can **add a candidate** (`source=<id>`) or **attach evidence** to a member. An output that maps to no member is a backlog row, not a feature |
| M2 UNIVERSE | Publishes a dated candidate set. Each name carries its sources and why it is in. Its age is printed on every receipt that consumes it. Stale (> 10 days) is red |
| M3 DECIDE | Every book declares the universe slice it draws from, and its decision rows cite the evidence ids that moved them |
| M4 ACT | Trades only what M3 decided, under a frozen contract, with the worst case in dollars printed |
| M5 LEARN | Writes back source weights, novelty and priors that the universe and the books read. A learner nobody reads is dead |
| M6 SHOW | Renders the universe, books and results from receipts, never from prose |

### 2a. The universe is a weighted graph, not a list (owner design, restated 2026-11-10)

The owner's words: a funnel of information flows in; "bubbles" (nodes) are connected to each other like a neural network, with weights; news lands on a node and the question is always **"what does this imply, where do these signals lead us?"** Example: a scandal hits a mega-cap CEO → that is immediate bad news for the name → *then* which suppliers, customers, competitors, ETFs and themes move, by how much, and which book acts. **Strategies and betas are instruments for learning; the graph is the product.**

| Piece | Definition | Exists today |
|---|---|---|
| Nodes | Companies (issuer id), themes / macro stations, people, commodities, countries, ETFs | Funnel list (25 of 5,339); global list 17.5k names in `contest/`; macro stations doc (inactive); WRDS identity rows stranded |
| Edges | supplier/customer, competitor, co-coverage (same analysts), co-mention (same news), sector/ETF membership, ownership | `graph_propagation.py` co-coverage graph (**no caller**, last receipt 09-12); `world_state` co-mention edges (last 11-03); ATLAS projection on an unmerged branch |
| Weights | Edge strength = how much of a shock on A historically shows up in B over 1/5/21 sessions, shrunk `n/(n+k)`; **rewritten by M5 from graded outcomes** | Not built |
| Propagation | Typed event on a node → signed, decayed impulse along edges → an **implications list** (name, direction, strength, path, why) with a receipt | Not built |
| Consumers | (1) funnel candidates `source='graph'`; (2) overlay / exit signals on books that hold affected names; (3) owner warning; (4) the desktop map | None wired |

Rules: every implication cites its path and is graded at its horizon (hit / miss / never-knowable); an edge that never predicts decays to zero; the mega-cap is a SENSOR (INVARIANTS), so its event is read for what it implies elsewhere; no implication may reach real capital.

## 5. How the work is executed (the agentic workflow)

1. **The orchestrator** (one session) reads TIER 0, this file and `WORK_LEDGER.md`. It claims the next `NOW` chunk and assigns builders. It edits only files it has claimed.
2. **Builders:** at most 5 at once (RAM). Each works in one sparse worktree from origin/main, created per chunk and **removed on merge**. No runtime data in worktrees.
3. **One writer per file**, across Claude, Codex and subagents, via `WORK_LEDGER.md`. Hot files have one owner per phase.
4. **An adversarial reviewer per chunk**: a different model plays an investor saying "you are wrong because…".
5. **Flow:** claim → build with targeted tests → review → fix → PR → `python -m scripts.ci_watch --wait` → merge → deploy or repoint → a verifier checks the acceptance receipt live → update **this file's row** plus one changelog line plus the RESULTS block. No PDF or handoff file per chunk; report in chat.
6. **Stop rules:** no consumer, no chunk · fix in place, never rebuild from scratch · a new guard cites its failure and exits non-zero · a pause carries an expiry · never commit growing data · never reset/stash/clean the runtime · never kill by image name · **never create a second roadmap**.
7. **Weekly scoreboard (in the changelog):** books with positions · substantive forecasts per day · FINDINGs · hypotheses killed or promoted · modules with no caller (debt) · worktree count · LLM spend per graded output.
8. **Definition of done (added 11-13).** A row is DONE only with all nine; with the first three and no consumer it is BUILT, and the weekly scoreboard counts both. (1) **Caller:** a scheduled task or an importing module that runs daily, named in the row. (2) **Receipt:** its own file advances each run; accepted on that, never on rc 0. (3) **Red state:** stale, empty or refused input exits non-zero and shows on the system page. (4) **Known answer:** a replay of a real past day where the right output is known. (5) **Consumer in the universe:** the node, book or learner that reads it, whose receipt cites it. (6) **Adversarial review** of the diff, one fix round. (7) **Expiry:** every switched-off flag, pause and forecast carries a date after which it is red or lapsed. (8) **Worst case in dollars** for anything that sizes. (9) **Control and by-year:** the result names its matched control and prints by year.
9. **The council (added 11-13).** For an owner message that carries new ideas, or a review of two weeks of graded calls: three experts, each given the message verbatim. *Evidence* (what research says, what Aegis already measured, the control that separates the idea from plain market exposure), *portfolio and risk* (instrument, construction, worst case in dollars), *architecture* (what exists, the home row, the caller and consumer). Round 1: each writes a position. Round 2: each corrects the other two. The brain decides, records disagreements, amends this file and asks the owner only what is his to decide. The council writes no code and merges nothing. First run 11-13: `aegis-recovery-evidence\s67-council-20261113\`.
10. **Order for the next three sessions (11-13 council; five builders at most; the brain does every runtime step).** *Session 1:* brain: CH-35 wiring (merge #136, pull, schedule), then the CH-14b observe-only runs. Builders: CH-44 · CH-42 · CH-11 note with CH-39 · the CH-38 dip study · the CH-20a replay.
