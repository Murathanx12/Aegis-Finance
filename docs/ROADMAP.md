## 1. Mission and end state

Build a self-improving investment intelligence system that maximises portfolio utility under a declared personality (preservation / balanced / aggressive / extreme growth). There are three deliverables:

1. **Murat's own capital.** Paper first; real money only through the attended CAPITAL_CANDIDATE gate.
2. **A public, accessible TOOL; the source code and research stay protected** (amended 2026-11-09). People use Aegis as a hosted product (site, API, desktop app), never as a repository to copy. The licence is All Rights Reserved. A public repository can be read and scraped by AI crawlers whatever its licence says, so in the end state **the source repo is private**, and the public surface is the hosted tool plus a curated showcase. See OD-9.
3. **An HKU paper**, if a novel and defensible result emerges.

## 2. The architecture this roadmap is organised around

```
              ┌──────────────── M5 LEARN (grades, priors, source weights) ───────────────┐
              ▼                                                                           │
  M1 SENSE ──► M2 UNIVERSE (the hub) ──► M3 DECIDE ──► M4 ACT ──► outcomes ──────────────┘
  news, reader,   dated candidate set,     books, branching,   paper accounts,
  official, macro, every name tagged with   overlays, owner      contest, PC-PAPER
  analysts, Asia   WHY it is in + age        hypotheses
                                │
                                └──► M6 SHOW: the public tool (results, universe map, alerts)
  M0 FOUNDATION underneath everything: runtime = a commit, storage, CI, budget, agent workflow
```

**The universe is the hub.** Every module connects to it through one contract:

| Module | Its contract with the universe |
|---|---|
| M1 SENSE | Every output maps to issuer ids, so it can **add a candidate** (`source=<id>`) or **attach evidence** to a member. An output that maps to no member is a backlog row, not a feature |
| M2 UNIVERSE | Publishes a dated candidate set. Each name carries its sources and why it is in. Its age is printed on every receipt that consumes it. Stale (> 10 days) is red |
| M3 DECIDE | Every book declares the universe slice it draws from, and its decision rows cite the evidence ids that moved them |
| M4 ACT | Trades only what M3 decided, under a frozen contract, with the worst case in dollars printed |
| M5 LEARN | Writes back source weights, novelty and priors that the universe and the books read. A learner nobody reads is dead |
| M6 SHOW | Renders the universe, books and results from receipts, never from prose |

## 5. How the work is executed (the agentic workflow)

1. **The orchestrator** (one session) reads TIER 0, this file and `WORK_LEDGER.md`. It claims the next `NOW` chunk and assigns builders. It edits only files it has claimed.
2. **Builders:** at most 5 at once (RAM). Each works in one sparse worktree from origin/main, created per chunk and **removed on merge**. No runtime data in worktrees.
3. **One writer per file**, across Claude, Codex and subagents, via `WORK_LEDGER.md`. Hot files have one owner per phase.
4. **An adversarial reviewer per chunk**: a different model plays an investor saying "you are wrong because…".
5. **Flow:** claim → build with targeted tests → review → fix → PR → `python -m scripts.ci_watch --wait` → merge → deploy or repoint → a verifier checks the acceptance receipt live → update **this file's row** plus one changelog line plus the RESULTS block. No PDF or handoff file per chunk; report in chat.
6. **Stop rules:** no consumer, no chunk · fix in place, never rebuild from scratch · a new guard cites its failure and exits non-zero · a pause carries an expiry · never commit growing data · never reset/stash/clean the runtime · never kill by image name · **never create a second roadmap**.
7. **Weekly scoreboard (in the changelog):** books with positions · substantive forecasts per day · FINDINGs · hypotheses killed or promoted · modules with no caller (debt) · worktree count · LLM spend per graded output.
