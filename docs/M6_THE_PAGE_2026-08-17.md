# M6 — the page, and the one number I had to measure before building it

**2026-08-17.** Order 9 routed M6 with the framing that settles it: *the research
just told us what it is allowed to say.* Building the page therefore started by
finding out what that was — and one load-bearing claim had never been tested.

---

## The gap I found before writing any UI

N18 reported **0 of 16 timing effects detectable** against matched-constant-
exposure controls, and I had written that up as *"the drawdown reduction is
average exposure."* That is what the test showed — but the test was on the
**declared personality objective**, `net return − λ × max drawdown`.

The page's central claim would rest on something else entirely: does targeting
constant volatility deliver **lower risk than holding the same average exposure
flat?** That is a different statistic and it had never been run.

So I ran it, on the same books, the same shared block resamples:

```
  policy                   outcome              delta       SE      MDE
  voltarget_10_cap1.0      annual volatility     -2.94     0.99     2.78  DETECTABLE
  voltarget_10_cap1.0      max drawdown         -20.46     5.98    16.75  DETECTABLE
  voltarget_15_cap1.0      annual volatility     -2.91     1.08     3.03  below MDE (0.96x)
  voltarget_15_cap1.0      max drawdown         -19.18     5.91    16.55  DETECTABLE
  voltarget_20_cap1.0      annual volatility     -2.44     0.97     2.71  below MDE
  voltarget_20_cap1.0      max drawdown         -13.55     4.95    13.86  below MDE
  voltarget_15_cap1.5      annual volatility     -4.41     1.49     4.16  DETECTABLE
  voltarget_15_cap1.5      max drawdown         -26.09     7.68    21.51  DETECTABLE

  volatility reductions detectable: 2 of 4 · drawdown reductions: 3 of 4
  across these 8 cells rho_bar = 0.670  =>  k_eff 1.41
```

**N18's null and this are both true and not in conflict.** The objective mixes
in a return term that is unresolvable on this window, and that noise swamped the
comparison. Isolating the risk statistic removes it.

So the honest sentence changes: **the rule is not merely "hold less"** — the
drawdown reduction against the same average exposure clears its MDE in three of
four configurations. But it is a **screen-grade result on the EXPLORE window at
k_eff ≈ 1.4**, and the tightest cell sits at 0.96× its own MDE, which by §37 is
exactly the shape of a number that looks like it working.

My previous write-up over-claimed the negative. Corrected in both directions:
utility improvement is not established, drawdown reduction is.

## What the page is

`/risk`, backed by `POST /api/risk-layer/exposure`. It shows **how much of the
book to hold** — never what to buy.

1. **The exposure now** — "Hold 81% of your book", with the realised volatility
   it was computed from.
2. **The one thing that would change its mind** — "it reaches the 100% cap if
   60-day realised volatility falls below 15.0%, and halves if it rises above
   37.0%." Thresholds, not a vibe: something checkable against the world
   tomorrow.
3. **The last twelve decisions and what each cost or earned** — each scored on
   the month that *followed* the decision, which is the only version anyone
   could have acted on. Green where holding less helped, red where it gave up
   return.
4. **The honest claim** — risk reduced by X; return effect **not established**;
   break-even sacrifice Y.
5. **The whole evidence record**, negatives included by name.

## Why the honesty is structural rather than editorial

The failure mode for a page like this is prose drift: the measurement says
"not established" and six weeks later the copy says "improves returns."

* `EVIDENCE` is a **frozen** dataclass. `test_the_evidence_record_cannot_be_
  edited_at_runtime` asserts it.
* `established` is `|effect| >= mde`, decided when the measurement ran.
  `test_every_established_claim_actually_clears_its_own_mde` recomputes it from
  the stored effect and MDE, so an editorial `established=True` fails the suite.
* `EVIDENCE.claim()` **raises** on an unknown outcome. There is no fallback, so
  a claim absent from the record has no code path that could render it.
* `stock_selection` is carried as an explicit **negative**, not omitted —
  absent would read as "not built yet"; present-and-false is the finding.
* `test_the_exposure_payload_never_names_a_ticker_to_buy` checks the response
  keys against a banned set. A future "top pick" field has to break a test to
  reach the page.
* The layer **refuses** rather than degrading: fewer than 40 observations → no
  exposure; an unpriceable book → 422, never a confident 1.0.

## Two things I got wrong building it

1. **The banned-word test scanned the serialised response for `"buy"`** and
   tripped on the comparator `"buy and hold"` — a legitimate name for the thing
   being measured against. A test that fires on its own vocabulary gets deleted,
   and then it protects nothing. Rewritten to check field *keys*.
2. **The guard contract caught my own new module on the next run.**
   `risk_layer` defines `RiskLayerRefused` and was not enrolled, so
   `test_every_guard_is_enrolled` failed. That is the contract from Order 8
   working on the first module added after it — enrolment by existing, exactly
   as intended.

## What it does not do

* No confirmation. 2006–2019 is the selection window; M4's confirmation window
  stays reserved and unspent because its MDE exceeds the effect.
* No multi-asset risk model. One equity book, one volatility estimate.
* No return promise, anywhere, in any state of the UI.
* The evidence is SPY-based while the exposure is applied to the user's own
  book. That transfer is an assumption, and it is the first thing a later
  version should measure rather than inherit.
