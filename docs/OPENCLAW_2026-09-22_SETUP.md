## What it is for, and what it must never touch

OpenClaw is the **research/browser sensor**. Its job is to read permitted web
sources — company IR pages, SEC filings, industry news, supplier and customer
announcements, analyst changes, product launches — and turn them into structured
event records carrying a timestamp and a source.

It is **not** an execution path. Brokerage stays on the API
(`backend/services/pc_broker.py`), and OpenClaw is never given an Alpaca login.
The separation matters for a reason beyond security: a browser agent that can
both form a view and act on it has no point at which the view is recorded, so
nothing can grade it afterwards. Evidence in, orders out, and a receipt between.

## The two things that need Murat

**1. A command owner.** `Capability: connected-no-operator-scope` means no
trusted human operator account is configured, so the agent cannot be granted
authority to act. This is set by attaching a chat channel:

```powershell
openclaw channels add
```

and completing one channel's setup. Until then OpenClaw runs but has no operator.

**2. The dedicated Google account.** The point of a separate identity is that
the agent's browser profile is isolated from your personal one — it cannot read
your mail, and a site that bans the agent does not ban you. Once the account
exists:

```powershell
openclaw browser open          # opens the agent-owned Chromium profile
```

then sign in to that Google account **inside that window**, plus any research
sites you legitimately have access to. Sessions persist in the managed profile.

**Do not sign the agent into Alpaca, a bank, or anything holding money.** If a
site's terms forbid automated access, it is out of scope — the value here is
breadth of public sources, not circumvention.

## The model

Murat: *"use a unblocked model or the current model we have."* DeepSeek is
wired, because it is this programme's only provisioned provider (CLAUDE.md: "THE
LLM PROVIDER IS DEEPSEEK, AND IT IS THE ONLY ONE"). The local `llama-server` is
the cheaper default for bulk reading and is already managed by
`backend/services/llama_server.py`; pointing OpenClaw at it as an
OpenAI-compatible endpoint is a config change, not a code change, and is owed
once the operator account exists.

**Cost discipline carries over.** DeepSeek answered `usage.model=deepseek-flash`
from 09-14, an **unpriced** model id, which makes every dollar cap a lower bound
of $0. Before any paid OpenClaw run, confirm the model id is priced — the cap
cannot bind on a model the ledger does not know how to price.

## What it is not allowed to do overnight

From the night contract: the local system may update **declared mutable policy
state** — source reliability, expert weights, watchlists, calibration — and may
**not** modify production source code. OpenClaw sits on the evidence side of
that line. It writes event records; it does not write Python.
