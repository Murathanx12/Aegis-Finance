# Saved-calendar discovery: guarded source candidate

Base: origin/main `40cdc5d57922fed49dd6fa8d6d67a44ded62b9a3`.
Guarded-send extension starts from preview candidate `a25b607a`.

`scripts.pre_event_owner_warning_discover` is a source-only candidate for the
existing 10-minute AegisOwnerEventWarning workflow. Preview remains the default.
It does not install, register, modify or activate a task or R launcher. No provider
requests, credential changes, trades, cursors or fabricated receipts are used.
No real send or native task invocation was performed while building/testing it.

The CLI takes `--receipt-dir`, `--pc-paper-ledger`,
`--expected-account-sha256` and `--journal-dir`. Directories must already exist.
`--send` additionally requires `--review`, a separately authored independent
exact-source review in the existing `pre-event-warning-review/1` format. A review
path alone does not enable sends. There is no caller-clock CLI option.

Discovery examines at most 64 directory entries (including unrelated and temp
files), refuses overflow rather than silently truncating, and uses a five-second
cooperative budget. It checks the existing protected IIF interval, private
capture/journal identities, frozen reads, published filename and seal,
saved-calendar replay, exact account pin and approved fresh snapshot selector.
Each receipt keeps its own observation clock. Checkout mtime is never evidence.
No recursive scan or provider fallback occurs. Private-root trust has the same
same-user replacement limitation documented by the existing capture/journal.
Local filesystem operations are not forcibly interrupted by the cooperative timer.

Eligible events are ordered by earliest ET date, newest embedded observation,
then filename. Any existing event attempt/result/pending journal path suppresses
that event conservatively, including corrupt or uncertain attempts. Discovery
never calls a sender to test duplicates or certifies an ACK. With no candidate,
JSON reports explicit NO_OP (empty/duplicate-only) or REFUSED (invalid inputs),
with counts. One valid candidate can coexist with corrupt/ineligible receipts.

The selected receipt bytes and private-root identities are rechecked before
exactly one call to `pre_event_owner_warning_once.run`. Preview disables send.
Send delegates with `send=True, review=...` and an additional pre-send callback
that rechecks those identities, exact selected bytes, IIF interval and discovery's
original five-second budget at every existing send checkpoint. The once runner's
own five-second pre-send budget remains binding, alongside the original discovery
budget; neither resets the other. Its existing ET event/IIF deadline and bounded
transport window remain unchanged. Durable reservation and ACK/duplicate handling
remain solely in the existing sender. Preview never reserves an event.

`once.SOURCE_PATHS` now includes discovery, in addition to its existing executable
dependencies. No new executable dependency was added. Send checks the independent
review before discovery and the once runner repeats its existing exact-source
checks before delivery. Missing, old, incomplete or mismatching reviews refuse;
review remains an independent-author trust attestation, not a signature or import
sandbox. No compatible independent approval file is generated by this candidate.

## Local adoption still required

A newly authored independent exact-source review receipt is required for this
changed source set. The previous preview-only review PASS and old sender review
receipts do not authorize sending from these changed bytes. A separate protected
local task/launcher adoption review is also required before installed use.
The installed task/launcher was not inspected or changed in this source-only
chunk. Treat the owner's stated 10-minute cadence as supplied context, not live
verification. The existing task cannot automatically use this isolated branch.

Offline tests exercise synthetic sealed receipt replay, one selected event,
empty/corrupt/multiple inputs, bounds, expiry, account/IIF refusal, root/receipt
mutation, ordering, missing/wrong/altered-source review, pending and confirmed
duplicate suppression. Provider/transport functions are forbidden by default;
only a bounded synthetic ACK stub replaces transport in delivery tests. Those
tests run the real once runner and durable journal against temporary fixtures.
The unchanged one-receipt suite also covers review gates and transport deadlines.
These checks are not an independent source review or local adoption approval.
