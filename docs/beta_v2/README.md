# Beta V2 canonical planning registry

Edit `registry.json` only. The roadmap, `request_coverage.json` and
`hypotheses.json` are deterministic projections generated by
`scripts/beta_v2_registry.py`. The JSON indexes include a digest of the normalized
canonical registry. No model, workbook recalculation or external service is
required to validate or render.

From the repository root:

```powershell
python scripts/beta_v2_registry.py validate
python scripts/beta_v2_registry.py attest --workbook <archived-owner-workbook.xlsx> --start <archived-00_START_CODEX.md>
python scripts/beta_v2_registry.py render
python scripts/beta_v2_registry.py check
$env:AEGIS_IGNORE_DOTENV = '1'
python -m pytest backend/tests/test_beta_v2_registry.py -q
```

`validate` is offline **structural** validation and explicitly reports
`source_status=UNVERIFIED`: it does not open private external archives. `check` additionally fails on
missing or stale projections. `render` validates first and writes only the three
projections. All commands return nonzero on errors. `--root` selects a checkout
or isolated test root; by default it is the checkout containing the script.

All authoritative JSON loading rejects duplicate keys at every depth, literal
NaN/Infinity, and overflowing numeric exponents. A conflicting last duplicate
status or source value cannot silently replace the first one.

## Explicit source attestation

`attest` is read-only and emits a JSON receipt. It verifies **both original
archived byte hashes** and the workbook's exact 17 task / 146 request / 28
hypothesis row bindings. It returns exit 0 only for `source_status: attested`;
missing archives return nonzero with `unverified`, and incorrect hashes,
ownership or baseline integrity return nonzero with `failed`. Without explicit
archive arguments it uses the registry's archive paths; relative paths resolve
against `--root`. Passing structural CI checks never substitutes for this
explicit private-source command.

`source_baseline.json` is a normalized immutable provenance baseline extracted
directly from the archived workbook, independently of the mutable registry.
It contains original IDs, sheet/row references, task prerequisites, request
ownership and archive digests, with no holdings or private history. Its exact
file SHA-256 is independently pinned in `scripts/beta_v2_registry.py` as
`SOURCE_BASELINE_SHA256`. The baseline never trusts a digest declared inside
the registry or inside itself. Structural checks also verify that baseline
pin and original request ownership without requiring the private archives.
Changing the baseline requires a reviewed source-version change and a separate
code-pin update; there is no auto-rebind command. Crosswalk/status/slice updates
do not change it. The pin provides version integrity, not cryptographic owner
authorization against someone able to rewrite both code and baseline.

## Sources and scope

The owner workbook's Roadmap rows 5–21, Requests rows 5–150 and Hypotheses rows
5–32 retain all 17 workstream IDs, 146 normalized request mappings and 28
hypotheses. Each entry names its source sheet and physical row. The archive
manifest records the original workbook and `00_START_CODEX.md` paths and SHA-256
digests. Those source archives remain outside Git. Requests contain the
workbook's normalized summaries, not raw private conversations or holdings.
The importer reads only the three planning sheets; it does not import any
portfolio, stock or holding reference sheet.

The one-time source-bound import is reproducible in an empty registry root:

```powershell
python scripts/beta_v2_registry.py import-workbook --workbook <owner-workbook.xlsx> --start <00_START_CODEX.md>
```

Import refuses to overwrite an existing registry, protecting later status and
evidence updates. Initial tasks are `proposed`, except parked B01 (`deferred`).
Requests marked verify-or-build in the workbook are `inherited-unverified`;
parked requests remain `deferred`. H01–H18 are inherited questions with prior
trials still to reconcile; H19–H28 remain `proposed`. Source status fields retain
the workbook wording. No source document title establishes completion.

All hypotheses have a **proposed administrative home in C09**, not an asserted
workbook mapping, pre-registration, permission to reopen a closed trial or
scientific result. Their comparison, previous report state and scope remain
source-bound. Before research execution, reconcile trial IDs, NEGATIVE_RESULTS,
power, instrument calibration and CANON. Preserve conditional and underpowered
findings and record exact revisit conditions.

## Status and evidence contract

Allowed states are `proposed`, `inherited-unverified`, `deferred`, `in-progress`,
`blocked` and `completed`. Every entry carries owner role, dependencies,
acceptance criteria, evidence, revisit condition and legacy aliases. Owners
are workbook roles, not claims that a particular worker is assigned or running.
Each request has exactly one canonical task; `source_task_id` retains the
workbook assignment. A routing change must retain that independently pinned
source owner and carry a `routing_override` with matching `source_task_id`,
new `task_id`, nonblank `rationale`, `reviewed_by`, timezone-qualified
`reviewed_at`, and `evidence: {path, sha256}` for an existing hashed repository
review receipt. A jointly edited task/source owner is refused. Merely adding a
rationale without reviewed evidence is insufficient.

Effective prerequisites derive from pinned workbook task edges plus current
task edges and request-specific extras, including original and routed task
prerequisites for an overridden request. Deleting copied request dependencies
or deleting the original edge on the parent task cannot waive admission.
Dependency removal is not supported by this contract; it requires a separately
reviewed contract/source change. Requests depend on the parent's prerequisites,
not on parent completion itself, avoiding a parent/request closure cycle.
Once those prerequisites legitimately close, reviewed scoped evidence may
complete a request while the larger parent workstream stays open. Dependencies
refer to workstreams and the effective graph must be acyclic.

For `completed`, every acceptance ID needs a structured evidence record:

```json
{
  "path": "relative/path/to/receipt.json",
  "sha256": "64 lowercase hexadecimal characters",
  "verified_at": "2026-10-25T12:00:00Z",
  "reviewer": "independent reviewer identity or review receipt ID",
  "summary": "What this artifact proves for the stated criterion",
  "acceptance_ids": ["R001:acceptance"]
}
```

The artifact must exist inside the selected repository root, match its hash,
and have a dated review with timezone. Invalid evidence is rejected even on
open entries. Completion also requires closed dependencies; a workstream
cannot complete while its mapped requests or hypotheses are open. Evidence
integrity and declared coverage do not establish scientific validity or runtime
effectiveness: an independent reviewer must adjudicate the acceptance criterion.
Tests or documents alone never establish deployment, investment benefit or
forward acceptance.

## Existing queues and unresolved legacy work

The implementation inspected `scripts/owner_queue.py` (phone question/link
inbox), `scripts/task_keeper.py` (scheduled task stewardship),
`scripts/night_queue_plan.py` (receipt-derived research proposals), and
`backend/services/task_receipts.py` (scheduled-output health). They retain their
existing ownership and stores. This registry is a planning source consumed by
its validator and renderer; it does not install a scheduler or another brain.

Workbook Requests column J says `RESOLVE_LOCALLY`; that marker is retained as
`source_legacy_id`, never manufactured into a legacy task ID. Empty
`legacy_aliases` with `legacy_resolution: inherited-unverified` means the
crosswalk is unresolved, not that prior work is missing, retired or complete.
The coordinator must bind exact current legacy IDs and receipts before adopting
or closing inherited work. V1/V1.1 unresolved continuation gates remain in
R024/C02; the exact four blockers are to be recovered, not guessed. All prior
roadmaps and histories remain preserved. This builder does not claim that the
logical workspace map or all of C01 is complete.

There is no activation, deployment, broker reset, NAV mutation, credential
handling or public publishing path in this module. Private working plans and
archive references are not an approved public showcase projection.

Hypotheses retain the reviewed administrative C00/C05 prerequisites even if
copied edges are removed. These prerequisites are not scientific registration.
Execution slices are advisory only: validated IDs, parents and dependency graph,
but no `completed` status until a scoped acceptance contract is implemented.
They cannot grant population/fleet acceptance or close parent workstreams.
