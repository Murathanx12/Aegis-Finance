# Private incremental WRDS acquisition

`scripts/wrds_c05_incremental.py` captures explicitly planned transcript creation-date cohorts into private Parquet artifacts. It does not publish into the native WRDS store, global price cache, account history or a trading consumer. A source commit is not runtime adoption or permission to replace an existing owner.

Use an independently reviewed, SHA256-pinned `C05_INCREMENTAL_PLAN/1` JSON document, an explicit timezone-aware stop time, and existing local libpq credential storage. The helper does not prompt, use a browser, or print credentials, account names, DSNs or raw database errors. A working web login does not establish database authentication or product entitlement. Actual SELECT receipts establish the specific accessible tables; transcript-person/detail access does not establish raw People Intelligence or KeyDev access.

The CLI requires `--plan`, `--plan-sha256` and `--stop-new-work-utc`. Its output root must resolve to the plan's own `artifacts` directory. Plans name an inclusive UTC transcript-creation start and exclusive end; all companies and collection/presentation versions in that interval are retained. The acquired tables include headers, components, speakers, type dimensions and, where accessible, transcript detail, companies and dated CUSIP/GVKEY links. These are source creation-date partitions, not claims of current event or market freshness. Remaining history, correction versions and other product families stay pending in the parent scope.

Every acquisition SELECT uses a unique named, non-holdable, forward cursor inside an explicit read-only transaction. The helper confirms transaction read-only state, obtains description after the first FETCH, closes the cursor and rolls back on success or failure, then restores autocommit. Rollback failure closes the connection. An aborted cursor's secondary CLOSE error does not erase the original entitlement SQLSTATE.

Production acquisition calls use the **default `batch_rows=2000`**. This argument is configurable on `stream_rows`; 2,000 is not an unconditional function hard cap. Each FETCH requests `min(batch_rows, max_rows - accepted_rows + 1)`. The default accepted-partition limits are 250,000 rows and 64 MiB of estimated logical data; production dimension calls set `max_rows=10000`. The row and logical-byte limits are also configurable function arguments. The live validation probe deliberately used batches of one row.

An extra row witnesses overflow, rather than silently truncating a declared complete partition. Logical size counts UTF-8 string bytes and estimates other scalar sizes. One large field or fetched batch can exceed the acceptance limit before refusal, and Python, Arrow and Parquet buffers require additional memory. These checks are **not RSS, wire-byte, server-work or whole-process memory limits**. Connection timeout is eight seconds; PostgreSQL statement timeout is 15 seconds, including FETCH statements. Application deadline checks surround execution/fetch; they are not an instantaneous process kill.

Only complete query results become content-addressed Parquet files. Saved bytes, row counts, columns and typed values are read back. Private manifests checkpoint atomically under a per-manifest FileLock. Completed/reused artifacts require matching hashes; reused artifacts also require matching row counts. Explicit 42501/42P01 refusals remain retained instead of blind entitlement retries. Inspect every job and run gate: process exit zero alone does not prove complete acquisition or downstream consumption.

The operator envelope supplies a separate cooperative worker lock, exact predecessor PID/creation and closed-result proof, source/plan/queue pins, exclusive audit outputs and reviewed queue transitions. A new lock or source edit cannot control an already loaded old process. Verify predecessor exit and lock release before replacement; do not kill processes by image name or silently repin a loaded sleeper. Review every new queue pin. Keep completed artifacts and earlier receipts intact.

This frozen helper contains the specific October 25, 2026 16:35–17:10 Singapore quiet-window refusal. It is not a recurring scheduler. The approved queue envelope expires at 18:00 that day, preventing subsequent-day execution under those receipts. Future envelopes must explicitly preserve the daily quiet window and receive their own review; this document does not authorize a perpetual background loop or scheduler change.

Offline consumer readbacks bind header/component IDs, ordered text hashes, section types, speaker roles, company/event joins and source identifier intervals. Preserve source unknown roles, one-to-many relationships, null dates and unresolved identifiers. A static company crosswalk is not automatically dated/PIT, CRSP, security-class or current-listing evidence. Data acquisition and mechanical readback do not establish model inference, forecasting quality or full-universe completion. Exclude validation duplicates from acquisition totals.

`backend/tests/test_wrds_c05_incremental.py` supplies 15 portable fake-cursor regressions against the actual AST-extracted `stream_rows` function, without importing the acquisition module, database SDKs or credential access. They cover lazy named execution, first-FETCH metadata/empty results, cap/EOF behavior, UTF-8 accounting, deadlines, read-only refusal, original SQLSTATE preservation and cleanup failures. Run only this focused file when checking the contract; a bounded actual server-cursor receipt is a separate operational qualification.
