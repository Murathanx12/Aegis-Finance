# Research: learning-loop for a paper-trading backtest engine + LLM memory
Started 2026-09-11. Web-only research, no repo edits.

## Task sections
1. LLM agents that learn from experience without weight updates
2. Turning backtest results into LLM context (experience distillation)
3. LLM-in-loop backtests with leakage control
4. Learning from thousands of paper portfolios (bandits, online portfolio selection, multiple testing)
5. Negative results re-opened (dead factors revived, sequential testing)
6. Self-attention + memory for numeric side (Decision Transformer etc.)

## Section 1 raw findings

**Reflexion (Shinn et al., NeurIPS 2023)** — arxiv.org/abs/2303.11366, github.com/noahshinn/reflexion
- Stores: free-form verbal self-reflections (text) in an episodic memory buffer, generated after each trial from task feedback (scalar or language, external or internally simulated).
- Retrieval: reflections appended to context on next trial (small sliding buffer, not vector-retrieved in original).
- Gains: coding (HumanEval 91% pass@1 GPT-4), ALFWorld decision-making, HotPotQA reasoning — large jumps over single-trial baselines.
- Failure modes (cited later): needs a verifiable success signal to reflect on; small buffer forgets old lessons; can reinforce a bad early narrative if no ground truth corrects it.

**ExpeL (Zhao et al., AAAI 2024)** — arxiv.org/abs/2308.10144
- Stores: cross-task natural-language "insights" extracted by comparing SUCCESSFUL vs FAILED trajectories (explicit contrastive pairs), plus a pool of past trajectories used as dynamic few-shot examples.
- Retrieval: similarity search over past trajectories + a standing insight list injected into the prompt.
- Gains: no parameter updates; beats ReAct/Reflexion on ALFWorld/WebShop/HotpotQA.
- Note: closest published design to "winner vs matched loser" — diffs success/fail trajectory PAIRS to write rules, matching Aegis's rule #4.

**Voyager (Wang et al., 2023)** — arxiv.org/abs/2305.16291, voyager.minedojo.org
- Stores: an ever-growing SKILL LIBRARY of executable, verified code (not text), indexed by embedding of the skill description.
- Retrieval: vector search over skill descriptions; self-verification loop (execute, check feedback, refine) before a skill is committed.
- Gains: 3.3x more unique items, 2.3x longer exploration, 15.3x faster milestones vs prior SOTA; skills transfer to new worlds/agents.
- Requires cheap, fast, re-executable, verifiable feedback per skill — a strategy variant (code + params, re-runnable in a backtest) fits this pattern well.

**Agent Workflow Memory (Wang/Zhou et al., 2024)** — arxiv.org/abs/2409.07429, github.com/zorazrw/agent-workflow-memory
- Stores: induced WORKFLOWS (reusable multi-step routines) abstracted from common sub-sequences in past successful trajectories, offline or online.
- Retrieval: relevant workflow text injected into the next episode's prompt.
- Gains: success-rate and step-efficiency gains on Mind2Web/WebArena; workflows generalize across similar sites/tasks.
- Failure mode flagged in "How Memory Management Impacts LLM Agents" (arxiv 2505.16067): agents over-rely on retrieved past experience ("experience-following") even when wrong for the current case — relevant to a "what we thought vs what happened" ledger, since stale retrieved experience can bias new forecasts.

**Generative Agents (Park et al., Stanford/Google, UIST 2023)** — arxiv.org/abs/2304.03442, github.com/joonspk-research/generative_agents
- Stores: append-only MEMORY STREAM of timestamped natural-language observations, plus periodically synthesized higher-level "reflections" and plans.
- Retrieval: relevance (embedding sim) x recency (exponential decay) x importance (LLM-scored), top-k retrieved per query — this 3-term scoring function is the standard retrieval recipe cited by nearly everything downstream.
- Gains: qualitative emergent believability (unplanned Valentine's party in a 25-agent sandbox); paper's own ablations show removing reflection/full memory degrades consistency.
- Failure modes: unbounded memory-stream growth (context/cost scaling) — the literal "memory bloat" failure mode; pure recency/relevance can surface stale/low-value memories at scale.

**FinMem (Yu et al., AAAI Symposium 2024)** — arxiv.org/abs/2311.13743, github.com/pipiku915/finmem-llm-stocktrading
- Stores: LAYERED memory (working/short/mid/long-term, explicit decay rates per layer, periodic promotion short->long based on access frequency), plus a "character/profile" design (risk personality).
- Retrieval: layer-aware, recency/importance/relevance weighted, similar machinery to Generative Agents.
- Gains: reported outperformance vs buy-and-hold/RL baselines on single-stock daily backtests (e.g. TSLA); the character/personality lever maps directly onto Aegis's four declared personalities.
- Caveat: single-stock, short windows, no visible discussion of realistic costs or holdout comparable to Aegis's standard — treat gains as illustrative, not evidentiary.

**FinAgent (Zhang et al., KDD 2024)** — arxiv.org/abs/2402.18485
- Stores: DIVERSIFIED memory split by module — market-intelligence memory (multimodal: price-chart images + text news + numeric indicators) vs a separate reflection memory.
- Retrieval: separate pipelines per memory type; a dual-level reflection (low-level recent-market, high-level strategy) — closest published analogue to Aegis's "text brain vs numeric net" split.
- Gains: claims >36% average profit improvement over 12 baselines across 6 datasets (stocks+crypto) — no visible cost/slippage/matched-control/per-era treatment matching Aegis's bar; treat as an inflated backtest-only claim, a "what not to trust" example.

**TextGrad (Yuksekgonul et al., 2024)** — arxiv.org/abs/2406.07496
- Not agent-memory: an "autodiff via text" framework — an LLM critiques an intermediate output/variable in a computation graph, and that critique is backpropagated as a "textual gradient" that revises upstream prompts/code.
- Relevant use: could convert a graded backtest outcome into a textual gradient that edits the strategy-generating prompt itself — a concrete mechanism for "turn learning into a markdown context file," since the gradient IS text describing what to change.
- Gains: reported improvements in code optimization, QA, prompt tuning, molecule/treatment design — general framework, not finance-specific, no finance benchmark found.

**DSPy (Khattab et al., Stanford, dspy.ai)**
- Not memory: compiles a pipeline of typed "Signatures" and optimizes few-shot demonstrations + instructions against a metric on a dev set (BootstrapFewShot, MIPROv2 Bayesian search).
- Relevant use: DSPy's optimizer is a mechanized "what worked, what didn't" search — could optimize the prompt that turns a backtest result into an LLM hypothesis/prediction, using a backtest-graded metric (e.g. Brier score) as the DSPy objective. Concrete, buildable mechanism.
- Caveat: needs a dev set and a scorable metric; overfits the prompt to the dev set exactly like overfitting a strategy — same multiplicity discipline (Holm/BH-FDR) should apply.

**In-context RL (survey line)** — arxiv.org/abs/2301.00234 (ICL survey), arxiv.org/abs/2404.00282 (LLM-enhanced RL survey), arxiv.org/abs/2506.06303 ("Reward Is Enough: LLMs Are In-Context RL Learners")
- A model trained/prompted on full RL histories (state/action/reward trajectories) can, without weight updates, act as if running policy iteration purely via context (Algorithm Distillation line, Laskin et al. 2022, and LLM-specific successors).
- Relevant: formal grounding for "an LLM reads its own paper-trading ledger in-context and improves" — but typically needs MANY in-context trajectories, and degrades under delayed/noisy reward, which daily P&L is.

### Which design fits "what we thought vs what happened, graded by Brier"?
ExpeL's paired success/fail insight extraction is closest structurally (diff winner vs matched loser -> rule). Generative Agents' recency x relevance x importance retrieval is the right retrieval MECHANISM once the ledger gets large. FinAgent/FinMem show finance-specific precedent for a text-memory/numeric-signal split. NONE of the surveyed designs score their verbal memories with a proper scoring rule (Brier) — that combination (verbal forecast graded like a forecaster) was not found in the agent-memory literature; it maps instead to Tetlock-style superforecaster scoring (see section 4). Flag as a genuine gap the project would be filling, not reproducing.

## Section 2 findings — experience distillation for trading agents

**RD-Agent / RD-Agent(Q) (Microsoft Research)** — github.com/microsoft/RD-Agent, microsoft.com/en-us/research articles
- Multi-agent Research (hypothesis generation, domain priors) + Development (Co-STEER code-gen agent) loop; maintains a "knowledge forest" that accumulates factor/model ideas and refines hypotheses across iterations — this is the closest thing to an evolving factor MEMORY in a real quant pipeline (built on Microsoft's Qlib).
- Reported: up to 2x annualized return with 70% FEWER factors vs classical factor libraries (i.e., the knowledge base helps it prune, not just add). No mention found of costs/slippage treatment to Aegis's standard — treat headline multiplier skeptically pending a memory-ablation number.

**QuantAgent (2024)** — arxiv.org/abs/2402.03755
- Two-loop architecture: INNER loop (Writer+Judge LLMs refine a response against a knowledge base, KB), OUTER loop (tests inner-loop output against real market data, feeds results back to enrich the shared KB). Framed as an MDP with theoretical sublinear-regret guarantees.
- Ablation-style evidence: MSE of a downstream XGBoost model trained on accumulated KB signals DECREASES monotonically as the KB grows (self-improvement curve); win-rate (pairwise LLM judgment of signal-to-idea relevance) increases with KB size — this IS the ablation the task asked for, though reported qualitatively as a curve rather than a single removed-vs-kept table cell.

**FinCon (NeurIPS 2024)** — arxiv.org/abs/2407.06567
- Manager-analyst hierarchical multi-agent system; the key mechanism is "conceptual verbal reinforcement" — an episodic self-critiquing step that updates a standing, shared, natural-language BELIEF about the market/strategy, which is selectively propagated only to the agent nodes that need it (reduces communication cost vs broadcasting to all agents).
- Ablation: FinCon WITHOUT within-episode CVaR risk control yields NEGATIVE cumulative returns and materially higher max drawdown vs buy-and-hold; removing the over-episode CVRF (conceptual verbal reinforcement) belief-update step also degrades returns/efficiency — a real memory-removed-vs-kept ablation, in the direction expected.

**TradingGPT (2023)** — arxiv.org/abs/2309.03736
- Multi-agent system, each agent has its own SHORT/MEDIUM/LONG layered memory with a decay mechanism, plus distinct "characters" (personalities) that communicate to form a collective strategy. Same layered-memory-plus-personality pattern as FinMem, applied to a multi-agent debate structure instead of one agent. Trained/evaluated on data Aug 2020–Aug 2023 — short window, no visible leakage control (pre-dates the "Profit Mirage" critique below).

**Alpha-GPT (2023/2024, KDD-adjacent, EMNLP 2025 demo)** — arxiv.org/abs/2308.00016
- NOT self-evolving memory — a human-AI INTERACTIVE alpha-mining framework: the human states an idea in natural language, the LLM translates it into a formal alpha expression via prompt engineering, evaluates it, and iterates with the human in the loop. Notable result: ranked top-10 of >41,000 teams in the WorldQuant International Quant Championship — a genuine, verifiable outside benchmark (not a self-reported backtest), which is unusually strong external validation for this literature.

**FactorMiner (Feb 2026)** — arxiv.org/abs/2602.14670, KDD v.2
- Most directly matches "turn backtest results into memory + reuse": a Modular Skill Architecture (executable evaluation tools, Voyager-style) + a structured Experience Memory that distills past mining trials into "successful patterns" AND "failure constraints" (both directions retained, not just winners — matches Aegis rule #4). Uses a "Ralph Loop": retrieve -> generate -> evaluate -> distill, explicitly reducing redundant search in a large, saturated alpha-factor search space (relevant given Aegis already runs "thousands of backtests").
- Sibling 2026 papers found in the same space: **AlphaMemo** (arxiv 2606.20625, "Structured Search-Process Memory for Self-Evolving Alpha Mining Agents") and **XAlpha** (arxiv 2607.08332, "Memory-Driven AI Quant Researcher for Hypothesis-to-Code Alpha Discovery") — a fast-moving 2026 cluster converging on exactly Aegis's ask (structured, distilled, bi-directional memory driving an LLM alpha-search loop). Worth a follow-up deep read of these three specifically before building, since they are the most recent and most on-target prior art found.

## CRITICAL cross-cutting finding for sections 2+3: leakage/backtest-illusion critiques

**"Profit Mirage: Revisiting Information Leakage in LLM-based Financial Agents"** (Oct 2025) — arxiv.org/abs/2510.07920
- Names the core failure "profit mirage": backtested LLM-agent returns look great and then evaporate once the evaluation period crosses the model's pretraining knowledge cutoff, because the LLM has MEMORIZED historical price moves and post-hoc news narratives rather than learned a causal driver.
- Quantifies leakage across four dimensions (exact dimension list not resolved from the abstract fetch — worth a follow-up read of the PDF if this becomes load-bearing) and releases **FinLake-Bench**, a leakage-robust evaluation benchmark.
- Proposes **FactFin**: a framework with a Strategy Code Generator + Retrieval-Augmented Generation + Monte Carlo Tree Search + a **Counterfactual Simulator** that applies counterfactual perturbations to news/inputs, forcing the agent to rely on causal structure rather than memorized outcome — directly the kind of "date-shifted placebo" / synthetic counterfactual control the task asked about in section 3.
- Compares a historical trade period (Q2-Q3 2021, inside typical pretraining data) vs a latest trade period (Q3-Q4 2024, outside it) under matched market conditions and shows significant degradation crossing the cutoff.

**"The Alpha Illusion: Reported Alpha from LLM Trading Agents Should Not Be Treated as Deployment Evidence"** (2026) — arxiv.org/html/2605.16895
- Direct empirical numbers on temporal contamination: **FinMem's returns drop ~72%** and **QuantAgent's Sharpe falls ~51%** when the evaluation window crosses the model's knowledge cutoff.
- Direct empirical numbers on cost realism: **TradingAgents' Sharpe falls 0.43 -> 0.22** after realistic frictions are charged; **QuantAgent's Sharpe goes 
  NEGATIVE, roughly -0.96 to -1.15**, once frictions are applied. This is a real-number version of exactly Aegis's own "costs are never omitted" rule (§ EXPLORE DIRTY PROMOTE CLEAN item 3) and a strong external confirmation that the rule is load-bearing, not paranoid.
- Flags a statistical-power problem: short eval windows (3-8 months, typical in this literature) give Sharpe confidence intervals WIDER than the reported gaps between competing systems — directly the same failure Aegis's own "sample the window before believing the t" and "a power flag built on the observed effect is the t-test" feedback items describe, now with an independent citation.
- Proposes six minimum-evidence protocols, **P1-P6**: P1 Temporal Integrity (post-cutoff windows, transparent knowledge boundaries), P2 Dynamic Universe (time-varying tradable set, delisting handled), P3 Counterfactual Robustness (direction-FLIP rate under reversed/counterfactual evidence — a concrete falsifiable test), P4 Epistemic Calibration (Expected Calibration Error, ECE — a formal Brier-adjacent metric), P5 Realistic Implementation (full friction stack: spread, commission, market impact, token/API cost), P6 Multi-Agent Disaggregation (single-agent baselines + homogeneity metrics, so a "multi-agent" win isn't just N copies of the same LLM voting together).
- Recommends NOT using LLMs as end-to-end trading deciders; instead treat them as "auditable information interfaces" feeding independent, separately-calibrated risk/execution modules downstream — i.e., the LLM proposes, a numeric/statistical layer disposes. This directly supports Aegis's existing architecture split (text "brain"/markdown context feeding a separate numeric net) rather than an LLM that sizes and executes trades itself.

## Section 3 findings — LLM-in-the-loop backtests with leakage control

**Lookahead Propensity / LAP (Gao, Jiang, Yan — "A Test of / Detecting Lookahead Bias in LLM Forecasts", Dec 2025, rev Jun 2026)** — arxiv.org/abs/2512.23847, ssrn.com/abstract=5985277
- Defines **Lookahead Propensity (LAP)**: a statistical estimate of how likely a given prompt (e.g., a specific firm-date news headline or earnings-call excerpt) appeared verbatim or near-verbatim in the LLM's training corpus.
- The TEST: if LAP correlates POSITIVELY with forecast accuracy, that correlation itself is diagnostic of lookahead bias (the model is doing lookup, not inference). Applied to (a) news headlines predicting stock returns and (b) earnings-call transcripts predicting capex.
- Result: predictive power was amplified specifically on HIGH-LAP firm-date pairs in both tasks, and the LAP-accuracy interaction LOST SIGNIFICANCE on post-training-cutoff samples — i.e., the "edge" was concentrated exactly where memorization was most likely and vanished out-of-sample. This is a concrete, reusable statistical test Aegis could implement: estimate LAP per prompt, check whether any measured edge concentrates in high-LAP cells, same family as "the winner was 5 months" (S42/S41 feedback already in Aegis's own memory) — external confirmation of the same diagnostic instinct.
- Companion paper by the same authors, "Debiasing LLMs by Fine-tuning" (arxiv 2604.02921), proposes a fine-tuning-based fix — likely not applicable to Aegis given DeepSeek-only/no-fine-tune constraint, but worth knowing it exists.

**ChronoBERT / ChronoGPT (He, Lv, Manela, Wu et al., Washington University in St. Louis; NBER w35247 Kelly et al.)** — arxiv.org/abs/2502.21206, huggingface.co/manelalab, NBER "Scaling Point-in-Time Language Models"
- "Chronologically consistent" LLMs: pretrained ONLY on text that would have been available as of each historical point in time, with yearly incremental releases (2000-2024, chrono-bert-v1-<date> snapshots on HuggingFace) — i.e., a genuinely point-in-time (PIT) LLM rather than a single frozen model with a cutoff.
- Financial result: `chrono-bert-v1-realtime`, evaluated 2008-01 to 2023-07, achieves a long-short portfolio Sharpe of **4.80**, beating BERT/FinBERT/StoriesLM-v1-1963, and comparable to Llama 3.1 8B (**4.90**) — i.e., a small, strictly-PIT model roughly matches a much larger modern model's Sharpe on this task, suggesting the modern model's edge is not (mostly) lookahead-driven here, OR that the task is easy enough not to need model scale. ChronoGPT-Instruct (generative variant) reports similarly "modest" lookahead bias vs. a much larger Llama baseline on next-day-return-from-news prediction.
- This is the "accepted control set" answer for section 3's last question at the strongest end: an actual family of open-weight, timestamped, re-trained-per-year LLMs, usable as a genuine placebo/control arm (predictions from a same-era model vs a frozen future-trained model on the identical PIT prompt) rather than a simulated one.

**Look-Ahead-Bench (2026)** — arxiv.org/abs/2601.13770, github.com/benstaf/lookaheadbench
- A standardized benchmark (methodologically closer to what Aegis would want to build/borrow) that evaluates lookahead bias in realistic financial WORKFLOWS (not just isolated Q&A recall probes), tracks "alpha decay" across temporally distinct market regimes as the diagnostic, and evaluates standard LLMs (**Llama 3.1 8B/70B, DeepSeek 3.2** — note DeepSeek is directly tested, relevant since Aegis's sole provider is DeepSeek) against a family of genuinely point-in-time "Pitinf" models.
- Finding: standard LLMs (including DeepSeek) show significant lookahead-driven alpha decay; the PIT "Pitinf" models do not, and actually improve with scale — i.e., scale helps a genuinely PIT model, but for a leaky model, scale mostly buys more memorization, not more reasoning.

**Anonymization: works less well than assumed, and can cost more than it saves**
- "Anonymization and Information Loss" (arxiv.org/abs/2511.15364): using S&P credit-downgrade prediction from raw vs anonymized financial text across multiple LLMs, finds anonymization DEGRADES predictive performance by stripping informative numeric and entity/relationship information (sector peers, supply-chain links), and — critically — this degradation is INDEPENDENT of and typically LARGER than the look-ahead-bias effect it's meant to prevent. Introduces the "anonymization gap" metric (measures the performance cost of anonymizing without needing ground-truth labels).
- MemGuard-Alpha (arxiv.org/abs/2603.26797, "Detecting and Filtering Memorization-Contaminated Signals in LLM-Based Financial Forecasting via Membership Inference and Cross-Model Disagreement") — could not extract full text (PDF fetch returned binary), but the title/abstract framing is directly on point: use (a) membership-inference-style probes to flag likely-memorized inputs and (b) DISAGREEMENT BETWEEN MULTIPLE LLMs on the same prompt as a signal that a forecast is reasoning rather than recalling (models that memorized the same training data tend to agree; models reasoning from a masked/perturbed prompt should show more independent variance). Cross-model disagreement is a cheap, implementable diagnostic Aegis could add without new infrastructure (DeepSeek is the only live provider, but the dormant Claude branch could serve as a second "voice" purely for this diagnostic, not for trading).
- Bearing on Aegis's already-measured results: this literature says the project's own finding "a 7B LLM reading an ANONYMISED monthly digest beats a shuffled-digest control" is BETTER evidence of genuine reasoning than a raw-text version would have been (anonymization, despite costing some signal, is exactly the right control when the concern is memorization) — but the same literature also says do not conclude from this that anonymization is free; measure the "anonymization gap" directly (raw vs anon performance on the SAME period) so the net effect (signal lost vs bias removed) is visible rather than assumed.

**Accepted control set, synthesized across all of section 3:**
1. Point-in-time / chronologically-consistent LLM as a genuine same-era control (ChronoBERT/ChronoGPT family) where feasible; otherwise
2. entity/date anonymization PLUS a measured "anonymization gap" (raw-vs-anon on identical dates) rather than assuming anonymization is costless;
3. date-shifted or shuffled-digest PLACEBO controls (Aegis already does the shuffled-digest version — R2 finding);
4. counterfactual/perturbed-news synthetic generation (FactFin's Counterfactual Simulator) to test whether direction flips when the counterfactual input flips (= "The Alpha Illusion" paper's P3 protocol, direction-flip rate);
5. a Lookahead-Propensity-style post hoc audit — check whether any measured edge concentrates in prompts most likely to have been memorized, and whether the edge survives on strictly-post-cutoff data;
6. cross-model / membership-inference disagreement as a cheap contamination flag.
No single control is sufficient alone in the papers found; P1-P6 (Alpha Illusion) and Look-Ahead-Bench both argue for layering several of these together and reporting per-era, matching Aegis's existing discipline.

## Section 4 findings — learning from thousands of paper portfolios

**Thompson Sampling / multi-armed bandits (Thompson 1933; Agrawal & Goyal 2012 regret bound)**
- Bayesian bandit: maintain a posterior over each "arm's" (strategy's) reward distribution, sample from each posterior, pick the arm with the highest sample — naturally balances explore/exploit, achieves logarithmic expected regret (Agrawal & Goyal, COLT 2012, proceedings.mlr.press/v23/agrawal12).
- HIERARCHICAL extension (general ML pattern, not finance-specific in what was found): pool a shared prior across strategy FAMILIES (e.g. all momentum variants share a family-level prior, all reversal variants share another) so a new variant of a known family starts with informed priors rather than a flat one — directly answers "shared prior" in the prompt; no single canonical finance paper pinned down, but the mechanism is standard hierarchical Bayes over bandit arms (partial pooling), and is exactly the fix for Aegis's arena problem where every book differs only in "portfolio treatment" (same signal family, near-identical priors currently, per the CLAUDE.md bottleneck note) — a hierarchical bandit would let strategy families compete at the top level and variants compete within a family, rather than flattening everything into COMPOSITE_WEIGHTS.
- Finance-specific bandit work found: "Strategy Selection Using Multi-Armed Bandit Algorithms in Financial Markets" (2024, ResearchGate) — compares MAB algorithms (incl. UCB) picking among strategies; "Improving Portfolio Optimization Results with Bandit Networks" (arxiv 2410.04217) — network-structured bandits for portfolio optimization; "Risk-aware multi-armed bandit problem with application to portfolio selection" (Royal Society Open Science) — incorporates a risk term (not just expected reward) into the bandit objective, relevant to Aegis's declared-utility framing (rule #3, four personalities) since a risk-blind bandit would just chase the highest-Sharpe arm regardless of declared risk preference.

**Online portfolio selection (Li & Hoi, ACM Computing Surveys 2014, arxiv.org/abs/1212.2129; book "Online Portfolio Selection: Principles and Algorithms")**
- Formalizes portfolio choice as sequential decision-making; taxonomy: Follow-the-Winner, Follow-the-Loser, Pattern-Matching, Meta-Learning (ensembles of experts).
- Universal Portfolios (Cover 1991, foundational, cited via this survey): a nonparametric algorithm achieves LOGARITHMIC regret vs the best-in-hindsight fixed-weight portfolio, i.e. a provable worst-case guarantee with NO distributional assumptions — the right theoretical anchor if Aegis wants to claim a bandit/ensemble-of-strategies layer is not just empirically better but provably bounded relative to the best strategy discovered after the fact.
- Meta-learning/expert-pooling algorithms here are essentially a non-Bayesian analogue of the hierarchical bandit above — worth comparing both families empirically since they have different regret guarantees under different assumptions (stochastic vs adversarial reward).

**Population-Based Training (Jaderberg et al., DeepMind 2017)** — arxiv.org/abs/1711.09846
- Not finance-specific: interleaves gradient-based training with evolutionary "exploit" (copy the weights+hyperparams of a better-performing population member) and "explore" (perturb hyperparams) steps across a population trained in parallel.
- Relevant as the direct analogue for Aegis's evolutionary strategy search (the G3_evolve run already in Aegis's own memory) — PBT formalizes exactly the "elites carried forward, seeds must differ" fix Aegis already discovered empirically (memory: "A DETERMINISTIC SEED SCHEDULE MAKES EVERY NIGHT A REPLAY"); citing PBT gives that fix an established name and a place in the literature (exploit/explore population dynamics) rather than being a from-scratch invention.

**Multiple testing / "how many trials" — the honest statistical treatment of running 1,000+ portfolios**
- **Harvey, Liu & Zhu, "…and the Cross-Section of Expected Returns"** (RFS 2016) — arxiv/NBER w20592: given the historical proliferation of factor tests in finance, argues the conventional t>2.0 significance bar is far too lax; estimates a newly discovered factor needs **t > 3.0** to clear a multiple-testing-adjusted bar. Directly the finance-specific analogue of Aegis's existing Holm/BH-FDR discipline, and a defensible number to cite for any EXPORT-track ("RESEARCH_CLAIM") significance threshold.
- **Bailey & López de Prado, "The Deflated Sharpe Ratio: Correcting for Selection Bias, Backtest Overfitting, and Non-Normality"** (2014) — deflates a reported Sharpe ratio by (a) the NUMBER OF TRIALS run (or estimated effective number of independent trials, via an Optimal-Number-of-Clusters unsupervised clustering step over correlated/overlapping strategies) and (b) skewness/kurtosis of the return series (non-normality). Directly answers "the right statistical treatment when 1,000+ portfolios are run at once" — Aegis already uses DSR per its CLAUDE.md standing rules; this citation and the ONC clustering detail (how to get the EFFECTIVE trial count when strategies overlap, rather than the naive raw count) is the piece worth double-checking against Aegis's current implementation.
- Companion: Bailey & Borwein, "The Probability of Backtest Overfitting" (PBO) — already referenced in Aegis's own memory (S38g "PBO 0.64"), so PBO is already in active use; DSR + PBO + Harvey-Liu-Zhu's t>3 together form a defensible three-part bar for anything promoted past PRODUCT_EXPERIMENT.

**Calibration / Brier / Tetlock scoring for a portfolio-level forecast ledger**
- Brier score = mean squared error between a stated probability and the {0,1} outcome; decomposes (Murphy 1973 decomposition, standard in the forecasting literature) into CALIBRATION (do 70%-confidence calls happen ~70% of the time — a reliability diagram plots stated probability bins vs observed frequency) and RESOLUTION/discrimination (does the forecaster actually distinguish likely-from-unlikely cases, not just hedge to the base rate) minus a base-rate uncertainty term.
- Tetlock's Good Judgment Project (IARPA forecasting tournament, "Superforecasting" book): superforecasters showed better calibration AND better resolution than regular forecasters and prediction markets in some tasks; forecasting skill was PERSISTENT (~70% retained "superforecaster" status year to year; year-to-year performance correlation ~0.65) — i.e., calibration/resolution skill is a real, measurably stable trait, not noise, which is the empirical justification for grading Aegis's LLM (or a human/LLM hybrid) on a rolling Brier ledger rather than dismissing it as unmeasurable.
- Practical ledger design implication: score every LLM/strategy probability forecast against its REALIZED outcome, keep a rolling reliability diagram, and report calibration and resolution SEPARATELY (not just headline Brier) so a well-calibrated-but-low-resolution forecaster (always says "50%") isn't confused with a genuinely skilled one — same "print raw beside excess" discipline already in Aegis's rules.

## Section 5 findings — negative results that should be re-opened

**Value factor revival, 2020-2022** — QuantPedia "Factor Trends and Cycles"; Two Centuries Investments; CFA Institute "Factor Performance: Will the Comeback Persist?"
- Value had its worst drawdown 2017-2022 (nadir August 2020, as growth/tech dominated the COVID period), then rebounded sharply: +27.3% long-short from the nadir, and Value beat Momentum and every other major factor in 2022; in 2022 broadly, almost all US factors were positive (avg +6.9%) with Momentum, Low Investment and Value beating their own long-run averages. Momentum itself crashed hard in 2009 and has been weak/flat post-2001 on average, with Value and Momentum negatively correlated enough that one's underperformance during the other's rally is expected, not anomalous.
- Lesson for Aegis: a factor that looks structurally dead over one multi-year window (value 2017-2020) can be a REGIME, not a mechanism failure — directly matches Aegis's own already-learned lesson ("SAME SIGN IN EVERY ERA IS NOT ALIVE TODAY" cuts the other way too: a factor dead in every recent era is not necessarily dead forever either) and supports pre-registering a NEW-DATA-ONLY re-test rather than treating "MECHANISM_REJECTED" as permanent by default.

**Regime-conditional factor timing** — "Factor Timing in Asset Management: A Literature Review" (2025); "Factors Timing Factors"; "Factor Timing with Portfolio Characteristics" (Review of Asset Pricing Studies); Hidden Markov Model regime-switching factor papers (MDPI 2020, arxiv 2410.14841)
- Four standard regime-identification families in the literature: macro/economic-cycle variables, fundamental valuation metrics, technical/market indicators, statistical regime-switching models (HMM etc.). Factor premia are demonstrably time-varying and regime-dependent; regime-conditioned dynamic allocation beats a static benchmark out-of-sample net of costs in several cited studies.
- Directly supports Aegis's "a global negative does not answer a conditional question that was never asked" (CLAUDE.md, scope-aware verdicts) — a mechanism rejected unconditionally may simply need a regime/era conditioning variable that the original test never included, and the literature has a standard toolkit (4 regime-ID families) for proposing that variable rather than inventing one ad hoc.

**Sequential testing / alpha spending / O'Brien-Fleming boundaries (biostatistics, transplantable to finance re-tests)** — Lan & DeMets alpha-spending function framework; O'Brien-Fleming boundary
- Alpha-spending: define an increasing function that allocates a total type-I-error budget (alpha) across a SEQUENCE of interim looks at accumulating data, without needing to pre-fix the number or spacing of looks. O'Brien-Fleming-style spending is conservative early (very high bar to stop/declare significant on an early look) and relaxes toward the pre-specified alpha only at the final planned look — this preserves most of the total error budget for the last, most-informed look.
- Direct transplant to a "closed hypothesis, re-tested on new data only" protocol: pre-register a total alpha budget for a MECHANISM_REJECTED idea's re-test, spend it via an O'Brien-Fleming-shaped schedule across sequential NEW-DATA-ONLY checkpoints (e.g. quarterly), and only reject/accept revival at the final checkpoint with most of the budget intact — this is precisely the machinery for Aegis's stated existing use ("the project already uses these for one trial," per the task's framing) generalized to any retired idea, not just one.
- No finance-specific paper explicitly doing "O'Brien-Fleming for factor re-tests" was found in this pass — this is an adaptation, not a citation of an existing finance paper; flag it as a methodology TRANSPLANT (biostatistics -> finance), which should be named as such if written up, not attributed to a finance source that doesn't exist.

**Publication bias / factor zoo / post-publication decay** — McLean & Pontiff (2016, JF), "Does Academic Research Destroy Stock Return Predictability?"; Feng, Giglio & Xiu "Taming the Factor Zoo" (JF 2020, dachxiu.chicagobooth.edu/download/ZOO.pdf)
- McLean & Pontiff: out-of-sample returns to 97 published anomalies were ~26% lower than in-sample (consistent with plain statistical overfitting in the original study), and returns were a further ~58% lower AFTER formal publication specifically (consistent with either informed trading against the anomaly once public, or continued data mining/crowding) — a clean empirical decomposition of "how much of a factor's decay is overfitting vs how much is publication-induced crowding," which is exactly the kind of decomposition Aegis would want before deciding whether a DEPRIORITIZED mechanism is dead from overfitting (won't revive) or dead from crowding (could revive if crowding unwinds, e.g. after a value-style rotation).
- Feng-Giglio-Xiu "Taming the Factor Zoo": proposes formally testing whether a NEW candidate factor adds incremental explanatory power over an existing factor set (rather than testing in isolation) — a multiple-testing-aware alternative to univariate factor mining, relevant to Aegis's own concern about `arena_composite` folding a new mechanism into existing weights and hiding whether its errors are different errors (CLAUDE.md "THE BOTTLENECK" section) — this is a formal statistical procedure for exactly that concern (marginal contribution testing) rather than Aegis's current informal "never fold in, always separate book" rule; worth comparing the two approaches.
- Consensus finding across this literature: value, momentum, quality/profitability, and low-volatility are the small set of factors that have survived rigorous OOS testing, multiple-testing correction, and cross-market replication — everything else in the "factor zoo" (hundreds of published anomalies) should be treated with a strong prior toward publication-bias-driven decay unless independently re-derived.

## Section 6 findings — self-attention + memory for the numeric side

**Decision Transformer (Chen et al., NeurIPS 2021)** — arxiv.org/abs/2106.01345
- Recasts offline RL as conditional sequence modeling: a causally-masked Transformer autoregressively predicts the next ACTION conditioned on a desired RETURN-TO-GO plus the history of (return, state, action) tuples — no value function, no policy gradient, just "generate the action that would follow this reward-conditioned history," trained purely on offline (already-collected) trajectories.
- Trading-specific implementations exist (github.com/ra9hur/Decision-Transformers-For-Trading) but no rigorous peer-reviewed evidence found in this pass that a Decision-Transformer-style architecture BEATS a tabular gradient-boosted-tree baseline on cross-sectional equity returns specifically — the trading repos found are demonstrations/reimplementations, not benchmarked research papers with the tabular-GBM comparison the task asked for. Treat "does it beat GBM cross-sectionally" as an OPEN question, not settled by existing literature.
- Relevant framing for Aegis: a Decision-Transformer-style model conditioned on a DECLARED utility/return target could be a formal way to implement the four personalities (preservation/balanced/aggressive/extreme growth) as different return-to-go conditioning targets fed to the SAME trained sequence model, rather than four separately-tuned strategies — worth flagging as a candidate architecture, not a validated one.

**"Trading as conversation" / LLM-as-sequence-agent line** — TradingAgents (arxiv 2412.20138), TraderTalk (arxiv 2410.21280)
- TradingAgents: role-specialized LLM sub-agents (fundamental/sentiment/technical analysts + risk-profiled traders) communicating in natural language rather than a single sequence-model architecture — this is an LLM-multi-agent pattern, not a numeric self-attention-over-trajectories pattern; keep it filed under section 2's multi-agent memory family, not section 6's numeric sequence-model family.
- TraderTalk: augments classical agent-based market MODELS (not a single trading strategy) with LLM-generated bilateral negotiation behavior to make simulated markets more realistic — a market SIMULATION tool (useful for generating richer synthetic counterparties in a backtest), not a forecasting/decision architecture.
- No paper found in this pass that is literally "self-attention over a sequence of (event, outcome) pairs conditioned on the portfolio's own history, benchmarked against tabular GBM" — closest analogue is Decision Transformer (above), unvalidated in finance vs GBM.

**Time-series foundation models finetuned on portfolio/return series (TimesFM and peers)**
- TimesFM (Google Research, decoder-only, 200M params, pretrained on 100B time points, github.com/google-research/timesfm): finetuned variants reported for Value-at-Risk forecasting (S&P100, 8.5 years OOS, beats traditional VaR methods on actual-over-expected ratio — arxiv 2410.11773) and realized-volatility forecasting (incremental/continual finetuning improves accuracy and statistically beats traditional models — arxiv 2505.11163) and general return forecasting (arxiv 2412.09880 "Financial Fine-tuning a Large Time Series Model", arxiv 2606.27100 "Pretrained Time-Series Foundation Models for Financial Return Forecasting").
- Headline caveat directly in this literature's own framing: "pretrained time-series foundation models are strong practical defaults for LOW-DATA, per-asset financial return forecasting, but their superiority is NOT universal" — i.e., the evidence supports TimesFM-style finetunes specifically in low-data/single-asset regimes (VaR, single-name vol), not as a general claim of beating tabular GBM on the CROSS-SECTIONAL stock-return prediction task Gu-Kelly-Xiu benchmark (below). No paper found running a TimesFM finetune head-to-head against LightGBM on the standard cross-sectional return-prediction task.

**Gu, Kelly & Xiu, "Empirical Asset Pricing via Machine Learning" (RFS 2020)** — dachxiu.chicagobooth.edu/download/ML.pdf — THE benchmark paper for "does anything beat tabular GBM on cross-sectional returns"
- Systematically compares generalized linear models, dimension reduction (PCA/PLS), boosted regression trees, random forests, and neural networks (up to 5 layers) on cross-sectional U.S. equity return prediction; establishes an out-of-sample R^2 standard for the field.
- Result: TREES (boosted trees, random forests) and NEURAL NETWORKS are the best performers, both clearly ahead of linear/generalized-linear baselines; gains trace to both methods' ability to capture NONLINEAR interactions among predictors that linear models miss. Trees and deep nets are roughly comparable top performers in their setup (deep NN was their benchmark for later analysis) — i.e., THE established answer is "gradient-boosted trees and moderately deep feedforward nets are both good and roughly comparable; nothing exotic (attention-over-sequences, self-attention memory architectures) was shown to beat plain trees" as of this foundational paper. This is the correct baseline to beat, and the honest state of the evidence found in this research pass is that no self-attention/memory/sequence architecture has been shown in a rigorous benchmark to beat this GBM/moderate-NN standard on cross-sectional returns specifically — Aegis should treat any internally-built Decision-Transformer-style or TimesFM-style numeric net as needing to clear THIS bar, with GBM as the control, exactly as Aegis's own CLAUDE.md rules already imply (LightGBM handles NaN, purged CV, walk-forward).
