## What landed

### 1. Public receipts (C19 review F12, C4 review F6)

- New: `backend/services/publish_receipts.py` and `python -m scripts.publish_receipts [--dry-run]`.
- **What is published:** the payload each public page's router serves, built from the newest
  receipts by the same builders (`legibility.*_payload`, `opportunities.load_latest`).
- **Where:** the TRACKED `backend/data/public_receipts/<kind>/latest.json`, plus `MANIFEST.json`.
- **Why the page payload and not a raw receipt copy.** The payload is the receipt trimmed to what
  the page needs. A raw ROI or health receipt has no allow-list, so copying it would publish
  fields nobody reviewed. Every source receipt the payload was built from is named in the
  manifest with the sha256 of the bytes read and its own stamp.
- **Sanitised at copy time with the routers' own sanitiser.** Each copy goes through
  `legibility_sanitise.sanitise(payload, SPEC[kind])`; the C19 review warned that a tracked
  folder is a second publication channel. A copy is then REFUSED (its previous copy stays) unless:
  - it is a fixed point of the sanitiser (`sanitise(x) == x`), and
  - `leak_scan` finds no denied key, user path, broker account id, PID or loopback address.

  A new allow-list `SPEC["opportunities"]` covers the Explorer. In the Explorer's public copy:
  - URLs are dropped; the router rebuilds click-through links from the ticker.
  - `analyst_reputation` is not published; the page does not render it.
  - Owner-personal lists (`murat_*`) are dropped.
  - The owner's name in shortlist provenance becomes "the owner".
  - Rows are capped at 250 per list in receipt order. Only `analyst_upside_v3` (700 rows) is
    cut, and the page shows the receipt's row count.
  - Per name: news is capped at 3 items, catalysts at 5, and insider and politician trades at 3.
- **Size budget:** `config.PUBLIC_RECEIPTS_MAX_BYTES = 5_000_000`. When the new set would exceed
  it, the publish is REFUSED and nothing is written. The first dry run hit this: 6.36 MB with the
  full Explorer. That is why the Explorer copy is trimmed.
- **How the routers choose:**
  - Live receipts are served first.
  - The published copy is served when the live build finds nothing, or finds fewer of the page's
    receipts than the copy names. The Railway checkout is the case this covers: the hyp_lab
    ledger is tracked but the boards are not.
  - When the copy is served, the payload says so in `served_from` and `published_utc`.
  - Ages are recomputed at serve time from each receipt's own stamp, so a stale copy reads STALE.
  - Routes affected: `/api/arena/v1/latest`, `/api/arena/v1/stories` (default query only),
    `/api/legibility/v1/{forecast-lab, theory-lab?board=sticky|basket, system-health}` and
    `/api/opportunities/*`.
- **The public folder is a sibling of the ledger dir, never a fixed path.** It is
  `<OPTIMUS_LEDGER_DIR>/../public_receipts`. A test that points the ledger dir at tmp therefore
  never reads the real copies, and the existing "404 without receipts" tests still hold.
- **Caller:** `task_keeper catalog` (the `AegisDataCatalog` daily firing) runs
  `run_opportunities` and then `run_publish_receipts` LAST, so the copies include what ran
  before. Each writes one keeper row (`task_keeper/opportunities.jsonl`,
  `task_keeper/publish_receipts.jsonl`). `task_receipts.r_catalog` folds both into the
  `task:AegisDataCatalog` health row, and a refused step degrades that row by name.
- **WHAT MAKES THE PAGES PUBLIC is the daily commit of `backend/data/public_receipts/` and the
  push that deploys it.** Writing the folder publishes nothing. Until a commit lands, Railway
  serves the previous commit's copy, aged honestly.

  previous period's SPY).
- When the lagged correlation wins, the value is `NOT_CREDIBLE`. The `why` reads

### 5. nn_lab revisions log (C5 review F9)

- **The log is now a TIMELINE.** `append_revisions` appends when the hash differs from the
  LATEST state of `(date, symbol, kind[, label column])`, read across the live file and every
  rotated month.
- **Flip-flops are recorded.** A vendor flip-flop A → B → A is two revisions, B and then
  `REVERTED_TO_STORED`. That second row is written for a checked tail date of a frozen kind
  (features or membership, never an applied label) that produced no row tonight.
  A → B → C → B logs three.
- **Monthly rotation.** `rotate_revisions` moves CLOSED months into
  `nn_lab/revisions_archive/revisions_<YYYY-MM>.parquet`:
  - A month is closed by each row's own `asof_utc`, never the mtime.
  - The parquet is TRACKED: `.gitignore` un-ignores it.
  - A JSON manifest is written beside it: rows, kinds, first and last asof, the sha256 and the
    command.
  - A sealed month is written once; a second attempt is REFUSED and its rows stay live.
  - The rotation verifies that archive rows plus live rows equal the count before it.
- `nightly.step_append` passes `checked_from=tail_start` and rotates after the append. A rotation
  failure is a named REFUSED on the receipt and never fails the night.
- Today all 10,394 rows are October, so nothing rotates until the November nightly.

## Review fixes (REVIEW_2026-10-07_C15_C20_PUBLISH_AND_V3_CONTRACTS.md, 70/100), applied the same day

This section supersedes two claims above: "WHAT MAKES THE PAGES PUBLIC is the daily commit" (nothing performed that
commit) and "the published copy is served when the live build finds fewer receipts" (now by age).

- **H1: a caller that actually publishes.** `publish_receipts.commit_public_receipts`, run by
  `python -m scripts.publish_receipts --commit` and as the LAST step of the `AegisDataCatalog` firing
  (`task_keeper.run_publish_commit`):
  - It refuses, changing nothing, when:
    - the branch is not `main`;
    - anything outside `backend/data/public_receipts/` is staged;
    - the manifest is not `OK`;
    - a published file does not hash to the manifest.
  - Otherwise it runs `git add -- <folder>` and refuses when the folder's staged diff is empty.
  - It commits with `git commit -m "public receipts <published_utc> (data-only, sanitised; no code)" -- <folder>`.
    The path-limited commit cannot take anything else.
  - It pushes `origin main`, but never when `main` carries unpushed commits that touch paths outside the folder
    (a data job never pushes code).
  - No hook is skipped.
  - One row per attempt goes to `task_keeper/publish_commit.jsonl`, and the `AegisDataCatalog` health row folds it in.
  - The Vercel workflow is filtered to `frontend/**` and does not fire. `ci.yml` runs on every push to main,
    so a daily data commit costs one CI run a day.
  - Tested on a throwaway repo with a bare remote, never the real repository:
    - off main;
    - staged code;
    - a tampered manifest;
    - a commit containing only the folder, pushed, then an empty-diff refusal;
    - unpushed code on main, where the commit is kept local and not pushed.
  - **On this machine right now** (branch `wip/2026-10-06-v1-beta`) `--commit` prints:
    ```
    commit: REFUSED
      REFUSED: current branch is 'wip/2026-10-06-v1-beta', not 'main': the public site builds from main; this job never switches branches
    ```
    So the pages become public only once this work is merged and the scheduled firing runs on a `main` checkout.
- **M1: precedence by age.**
  - The newer of live and published wins, by the newest receipt stamp. Ties go to completeness, then to live.
  - On a served copy, Arena rows' `mark_status` / `mark_age_days` are recomputed from serve time
    (`age + days since the ROI stamp`, LIVE becomes STALE past `PAPER_ACCOUNT_MARK_STALE_DAYS`), and so are
    `mark_status_counts` and the health rows' `age_s_now`.
- **M2: the owner's identity.**
  - It is scrubbed from every kind, case-insensitive, to "the owner", and it is in `leak_scan`; a hit REFUSES.
  - The patterns are:
    - `config.OWNER_NAME_PATTERNS` (name + GitHub handle);
    - env `AEGIS_OWNER_PATTERNS`;
    - the git e-mail local part and the home-folder name, derived at runtime and never written into the repo.
- **M3: supersession validation.**
  - `--supersedes R` is refused before scoring, and `write_supersessions` refuses (the previous file is kept),
    unless all of these hold:
    - R's summary exists;
    - R has the same twin kind;
    - R is older by its own `written_utc`;
    - R scored the rule;
    - no other supplement claims (R, rule).
  - `BACKFILL_SUPERSEDES` is pinned at its two entries by a test.
  - The real folder validates with no refusals.
- **M4: C10's seal rule.**
  - Rotation is two-phase. It seals (parquet + manifest), and rows leave the live file only when
    `verify_month_seal` holds:
    - the parquet hashes to the manifest;
    - git TRACKS it (`ledger_archive.is_tracked`, or the same `git ls-files --error-unmatch` question under
      nn_lab's own venv, which cannot import backend.config);
    - the live rows of that month equal the archived rows.
  - Until the owner commits the parquet the month reads `SEALED_PENDING_COMMIT` and every row stays live.
  - `revisions_history` re-hashes every archived month and raises on a mismatch.
- **M5: memory floor.**
  - The Explorer build is REFUSED (logged, never started) below 4.0 GB free.
  - Free memory is read with `GlobalMemoryStatusEx`, the reading `bridges_on_crsp` uses; psutil is not installed.
  - An unreadable value refuses too.
  - 5.3 GB was free when this was written.
